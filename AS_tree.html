6.1 Árvores de decisão para regressão

As árvores de decisão foram inicialmente propostas para problemas de classificação, porém, podem ser adaptadas de forma simples para problemas de regressão. Na regressão por árvores de decisão, ou simplesmente por árvores de regressão, divide-se o espaço preditor em várias regiões hiper-retangulares tomando como predição a média ou outra medida simples das observações de treino da região. O conjunto de regras de divisão usado para segmentar o espaço preditor pode ser resumido em um diagrama semelhante a uma árvore, conforme a Figura 6.1. A árvore plotada apresenta quatro nós terminais ou folhas e profundidade igual a 2, isto é, a partir do nó raiz são necessários no máximo 2 partições para atingir qualquer folha.

O gráfico de superfície da Figura 6.2 expõe o modelo obtido em função das duas variáveis preditoras, podendo-se observar que o valor previsto é constante em cada região retangular correspondente ao diagrama ilustrado anteriormente.

Pode-se observar o mesmo modelo de árvore de regressão via gráfico de contorno, conforme Figura 6.3, ficando mais clara a divisão do espaço preditor.

Sejam \(K\) preditores, \(\mathbf{x} = [x_{1}, x_{2},..., x_{K}]^T\), uma resposta, \(y \in \mathbb{R}\) , e \(n\) observações de treino, \(\mathcal{D}=(\mathbf{x}_1,y_1), (\mathbf{x}_2,y_2),..., (\mathbf{x}_n,y_n)\). O algoritmo (Classification and Regression Trees - CART) para regressão define, a cada iteração, a variável preditora e o seu nível para dividir o espaço dos preditores. Considerando \(J\) regiões \(R_1, R_2, ..., R_J\), o valor predito será uma constante \(\gamma_j\), em cada região, \(j=1,...,J\). Portanto, o modelo de árvore de regressão pode ser definido conforme a Equação 6.1, \(\{R_j,\gamma_j\}, j=1,\ldots,J\), onde \(I(\mathbf{x} \in R_j)\) é uma função indicativa que recebe 1 se \(\mathbf{x}\) pertence à região \(R_j\) e 0 caso contrário. O melhor \(\gamma_j\) para minimizar a soma dos quadrados dos erros é a média das observações na região, \(\hat{\gamma}_j = (\bar{y}_i | \mathbf{x}_i \in R_j)\).

\[ \begin{aligned} f(\mathbf{x}) = T(\mathbf{x},R_j,\gamma_j) = \sum_{j=1}^J \gamma_jI(\mathbf{x} \in R_j) \end{aligned} \tag{6.1}\]

Considerando todos os dados de treinamento, as divisões são definidas tomando uma variável para divisão, \(x_k\), \(k = 1,..., K\), e um ponto de divisão \(x_k = s\), \(R_1(k,s) = \{\mathbf{x}|x_k \leq s\}\) e \(R_2(k,s) = \{\mathbf{x}|x_k>s\}\). Portanto, o algoritmo CART busca o preditor para a divisão e o valor deste na divisão resolvendo a Equação 6.2, ou seja, minimizando a soma dos quadrados dos erros de previsão nas regiões obtidas a partir da escolha de \(x_k\) e seu valor \(s\).

\[ \begin{aligned} \min_{k,s} \Bigl[ \min_{\gamma_1} \sum_{x_i \in R_1(k,s)} (y_i - \gamma_1)^2 + \min_{\gamma_2} \sum_{x_i \in R_2(k,s)} (y_i - \gamma_2)^2 \Bigr] \end{aligned} \tag{6.2}\]

Importante

O algoritmo CART repete o particionamento recursivamente até um determinado critério de parada ser alcançado, por exemplo, até um número mínimo de observações em cada partição ser atingido ou até uma profundidade máxima da árvore.

Seja um conjunto de dados de preço de venda de apartamentos em algumas cidades pertencentes às regiões de Alto Paraopeba, Zona da Mata e Campos das Vertentes do estado de Minas Gerais. Os dados contém 632 observações constando a cidade, o bairro, a área, número de quartos, número de banheiros, número de salas, número de vagas na garagem, presença de varanda, área gourmet, terraço, copa e de piscina. Algumas linhas são aleatoriamente exibidas na Tabela 6.1.

A perda na Equação 6.2 consiste na perda em cada partição gerada no algoritmo CART. A Equação 6.3 expõe a função perda geral a ser minimizada, onde \(J\) é o número de nós terminais ou regiões finais do modelo, e o termo \(\alpha J\) consiste em uma penalização que controla o crescimento da árvore, sendo comumente chamado de termo de poda. O parâmetro \(\alpha\) é chamado de complexidade de custo e controla a intensidade dessa penalização.

\[ \begin{aligned} \min_{T} \sum_{j=1}^{J} \sum_{x_i \in R_j} (y_i - \gamma_{j})^2 + \alpha J \end{aligned} \tag{6.3}\]

Importante

Os hiperparâmetros a serem otimizados em modelos de árvore de regressão/decisão são a complexidade de custo, \(\alpha\), o número máximo de nós terminais ou folhas, \(J\), e o número mínimo de observações por partição (min_n).

Pode-se realizar uma validação cruzada para otimizar os hiperparâmetros do modelo de árvore de regressão, isto é, definir a profundidade da árvore e a complexidade de custo, \(\alpha\), ideais para os dados em análise e evitar o sobreajuste. A Figura 6.4 plota o erro em relação a profundidade e a complexidade da árvore. Neste caso, foi considerado min_n = 20. Observa-se que um modelo com profundidade igual a 4 e um valor de complexidade de custo de baixo a intermediário minimiza o erro de teste, isto é, minimiza RMSE ou maximiza \(R^2\).

6.1.1 Importância dos preditores

Os modelos de árvore de decisão e regressão são simples de interpretar, pois apresentam uma relação direta entre o espaço de decisão particionado e as previsões. As variáveis mais importantes neste tipo de modelo podem ser ranqueadas considerando a redução no erro quadrático de um nó pai para os filhos, segundo a Equação 6.4, onde \(SS_E\) consiste na soma dos quadrados dos erros.

\[ \text{Importância}(x_j) = \sum_{\text{splits com } x_j} \left(SS_{E_{\text{pai}}} - SS_{E_{\text{filho esq.}}} - SS_{E_{\text{filho dir.}}}\right) \tag{6.4}\]

A Figura 6.6 apresenta um gráfico de importância de variável, comumente chamado de Variance Importance Plot (VIP). Observa-se que a área do apartamento é o preditor mais importante no preço, seguido do número de vagas na garagem, número de banheiros, suites, etc. Sugere-se o estudo de outros modelos de árvore de decisão com número reduzido de variáveis, de forma a avaliar se é possível obter um modelo mais simples com menor erro.

6.2 Bagged trees ou bagging

Bagged trees ou bagging ou, em português, poderia ser traduzido de forma livre como “árvores ensacadas” e consiste em um método baseado em árvores de decisão que pode ser aplicado tanto em regressão quanto em classificação. O método agrega várias árvores de decisão as quais são estimadas a partir de reamostragem por reposição dos dados de treino. Ou seja, antes de estimar cada árvore, realiza-se um sorteio com reposição dos dados de treino, procedimento este chamado de bootstrap e, posteriormente, estima-se a árvore para cada amostra obtida por sorteio com reposição. O modelo final é a média de todas as árvores obtidas após bootstrap dos dados. Geralmente, um número alto de reamostragens é realizado e, portanto, um número alto de árvores é obtido, resultando em um modelo com maior flexibilidade, porém mais difícil de interpretar. O nome BAgging também vem de bootstrap aggregated ou agregação por bootstrap.

Definição

Bootstrap é uma técnica estatística de reamostragem por reposição, usada para inferência, simulação e estimativas. Por exemplo, seja um conjunto de dados de treino \(\mathcal{D}_{treino} = \{(\mathbf{x}_1,y_1), (\mathbf{x}_2,y_2),..., (\mathbf{x}_n,y_n)\}\), com \(n=7\) observações. Uma amostra bootstrap pode resultar no seguinte conjunto de dados \(\mathcal{D^*} = (\mathbf{x}_5,y_5), (\mathbf{x}_7,y_7), (\mathbf{x}_5,y_5),\) \((\mathbf{x}_4,y_4), (\mathbf{x}_7,y_7), (\mathbf{x}_3,y_3), (\mathbf{x}_1,y_1)\). Pode-se demonstrar que, para um \(n\) suficientemente grande, no bootstrap, a probabilidade de uma observação ser sorteada ao menos uma vez é igual a \(1-e^{-1} = 0,632\).

Considere um conjunto de dados de treino com \(n = 10\) observações, com três preditores e uma variável independente, exibido integralmente na Tabela 6.2. Cada linha é exibida com uma cor distinta para facilitar a distinção entre estas e entendimento do método bootstrap.

Um bootstrap deste conjunto de dados pode resultar na reamostragem exibida na Tabela 6.3. Pode-se observar que, neste caso, as observações 2, 4, 5, 6, 9 e 10 foram sorteadas, sendo as observações 4, 5, 6 e 9 sorteadas duas vezes, enquanto as observações 1, 3, 7 e 8 não foram sorteadas.

A Figura 6.7 exibe o diagrama de uma árvore de decisão para a amostra obtida via bootstrap. O bagging repete este processo diversas vezes, reamostrando os dados por bootstrap e estimando para cada “nova” amostra uma nova árvore. Ao final é tomada como predição a média de todas as árvores.

Para o mesmo conjunto de dados, sejam \(B=6\) árvores obtidas após reamostragens via bootstrap apresentadas na Figura 6.8. As árvores diferem entre si, pois cada reamostragem produz um conjunto de treino distinto — com repetições e ausências de observações originais — sendo a probabilidade de dois bootstraps coincidirem decrescente com \(n\).

Seja uma observação futura arbitrária com \(x_1=-1,11\), \(x_2=1,73\) e \(x_3=1,92\). Considerando as 6 árvores obtidas anteriormente, as previsões destas para esta observação são: 7,10, 3,51, 7,16, 7,18, 6,24 e 4,14. O modelo bagging retorna como resultado a média das previsões das árvores, conforme Equação 6.5, onde \(B\) consiste no número de árvores obtidas após bootstrap dos dados e \(T_b\) consiste na \(b\)-ésima árvore, \(b=1,...,B\). Logo, \(\hat{y} = \frac{1}{6}\sum_{b=1}^6 T_b(\mathbf{x}_0)\) = \((7,10+3,51+7,16+7,18+6,24+4,14)/6 = 5,89\).

\[ \hat{y} = \frac{1}{B}\sum_{b=1}^B T_b(\mathbf{x}) \tag{6.5}\]

Importante

Os hiperparâmetros do método bagging são a complexidade de custo, \(\alpha\), a profundidade da árvore, o número mínimo de observações por partição (min_n) e o número de bootstraps/árvores estimadas.

Seja novamente o caso de previsão do preço de apartamentos. A Figura 6.9 plota o RMSE em função dos hiperparâmetros na validação cruzada do modelo de regressão via bagging para prever o preço de apartamentos. Os níveis destes que minimizam RMSE são \(\alpha = 5,62 \times 10^{-4}\), profundidade da árvore igual a 8 e número mínimo de observações por partição min_n=11. Foram considerados 50 bootstraps e, logo, 50 árvores.

6.2.1 Importância dos preditores

A Figura 6.10 apresenta um gráfico de importância de variáveis do modelo bagging para prever o preço de apartamentos. Neste caso, o método de cálculo de importância das variáveis é a permutação. Observa-se que as variáveis mais importantes no preço são Area, Vaga, Cidade, etc. A linha vertical de referência consiste no RMSE de referência para o modelo sem permutação das variáveis. As variáveis com box-plot à direita da linha são aquelas que melhoram o ajuste do modelo.

Definição

A permutação é um método de medição da importância dos preditores a partir do embaralhamento dos valores destes, de forma a avaliar a perda ou ajuste em relação às previsões sem o embaralhamento. Espera-se que, para um preditor importante, o embaralhamento piore o ajuste do modelo.

A Figura 6.11 expõe um gráfico de efeitos, também dito gráfico de dependência parcial, do modelo de regressão obtido via bagging para prever o valor do apartamento em função da área e do número de vagas para carros na garagem. Os outros preditores foram fixados em Quartos = 3, Banheiros = 2, Varanda = "N", Suite = 1, Sala = 1, Copa = "N" e Piscina = "N". Observa-se aumento do preço em função da área e número de vagas. Juiz de Fora é a cidade com maiores preços. Tal gráfico pode ser realizado para outras variáveis do modelo.

6.3 Floresta aleatória

O modelo de floresta aleatória consiste em uma evolução do modelo bagging com a finalidade de diminuir a variância deste. Basicamente, em casos onde há multicolinearidade, isto é, correlação entre os múltiplos preditores, o bagging pode acarretar na seleção de apenas alguns dos preditores disponíveis durante o particionamento binário recursivo, os quais apresentam efeito maior e dominariam este processo. Neste caso, as árvores geradas considerando a reamostragem das observações de treino apresentariam alta correlação entre si, acarretando em alta variabilidade das previsões finais. No modelo de floresta aleatória, antes de cada partição, são selecionadas aleatoriamente \(m\) variáveis regressoras, \(m<K\), às quais são consideradas no processo de particionamento binário. Geralmente, para regressão recomenda-se \(m=K/3\). Entretanto, este parâmetro pode ser melhor definido via validação cruzada.

Importante

Os hiperparâmetros do método floresta aleatória são o número de bootstraps/árvores, o número de preditores sorteados e considerados em cada particionamento binário recursivo, m (mtry) e o número mínimo de observações por partição (min_n).

A Figura 6.12 plota o RMSE em função dos hiperparâmetros na validação cruzada do modelo de regressão via bagging para prever o preço de apartamentos. Os níveis que minimizam RMSE são \(m = 4\), 1000 árvores e min_n=2.

6.3.1 Importância dos preditores

A Figura 6.13 expõe o gráfico de importância das variáveis por permutação do modelo de floresta aleatória para prever o preço de apartamentos. As primeiras variáveis mais importantes coincidem com as do modelo obtido via bagging. Sugere-se ao leitor comparar ambos resultados e verificar as diferenças na ordem de importância das variáveis.

Definindo a receita. A especificação step_unknown cria a categoria “unknown” para valores NA (desconhecidos) de um preditores categóricos. Por exemplo, pode-se observar que nos dados de treino a décima observação não apresenta o bairro. Já a especificação step_other une categorias infrequentes em uma categoria chamada de “other”, podendo-se definir a proporção de observações de corte com o argumento threshold, sendo 0,05 o default. O preditor Bairro apresenta muitas categorias, possivelmente com baixa frequência, sendo interessante neste caso o uso de tal especificação.

receita <- recipe(formula = Valor ~ ., 
                  data = dados_treino) |>
  step_unknown(all_nominal_predictors()) |>
  step_other(all_nominal_predictors()) |>
  step_dummy(all_nominal_predictors())

receita |> 
  prep() |> 
  bake(dados_treino)
Importante

Nos modelos baseados em árvores não é necessário a normalização dos preditores, uma vez que o processo de particionamento binário recursivo é invariante a escala.

Definindo o método. Para árvore de decisão/regressão usa-se decision_tree e sugere-se o pacote rpart. Nos métodos que podem ser aplicados tanto a regressão quanto a classificação é importante definir o seu objetivo via set_mode.

tree_model <- 
  decision_tree(cost_complexity = tune(),
                tree_depth = tune()) |>
  set_engine("rpart") |>
  set_mode("regression")

Definindo o grid para estimar os hiperparâmetros via grid_regular, com 5 níveis para cada hiperparâmetro. O particionamento dos dados é realizado via vfold_cv, para validação cruzada e grid search. Em seguida, define-se o workflow e, por fim, realiza-se a otimização de hiperparâmetros via tune_grid.

tree_grid <- grid_regular(cost_complexity(),
                          tree_depth(),
                          levels = 5)

set.seed(234)
cell_folds <- vfold_cv(dados_treino, 
                       v = 5)

set.seed(345)
tree_wf <- workflow() |>
  add_recipe(receita) |>
  add_model(tree_model) 
  
tree_res <- 
  tree_wf |> 
  tune_grid(
    resamples = cell_folds,
    grid = tree_grid
    )

Coletando métricas de ajuste na validação cruzada via collect_metrics, filtrando e ordenando por RMSE.

tree_res |>
  collect_metrics() |>
  filter(.metric == "rmse") |>

Para a métrica \(R^2\) deve-se ordenar de forma ascendente.

tree_res |>
  collect_metrics() |>

library(baguette) # para bagging
library(forcats) # function fct_reorder para permutacao

Definindo método bagging via bag_tree. Os hiperparâmetros possíveis de serem definidos ou otimizados são a profundidade da árvore via tree_depth, o número mínimo de observações por partição via min_n e o \(\alpha\) ou complexidade de custo via cost_complexity. O número de bootstraps/árvores é definido ao se selecionar o pacote, via argumento times. Sugere-se usar o pacote rpart para modelos de árvores de decisão/regressão.

bag_model <- 
  bag_tree(tree_depth = tune(), 
           min_n = tune(), 
           cost_complexity = tune()) |>

Para avaliar a importância de variáveis via permutação, sugere-se usar as funções explain e model_parts ambas do pacote DALEX. Com plot(vip_bag) já seria possível plotar um VIP. Entretanto, a função ggplot_imp exposta abaixo, desenvolvida por Kuhn e Silge (2022), viabiliza uma saída mais elegante.

explainer_bag <- explain(
  model       = final_bag_fit,
  data        = dados_treino |> select(-Valor),
  y           = dados_treino$Valor,
  label       = "Bagging",
  predict_function = function(model, newdata) predict(model, newdata)$.pred,
  verbose = F
)

ggplot_imp <- function(...) {
  obj <- list(...)
  metric_name <- attr(obj[[1]], "loss_name")
  metric_lab <- paste(metric_name, 
                      "depois da permutação")
  
  full_vip <- bind_rows(obj) %>%
    filter(variable != "_baseline_")
  
  perm_vals <- full_vip %>% 
    filter(variable == "_full_model_") %>% 
    group_by(label) %>% 
    summarise(dropout_loss = mean(dropout_loss))
  
  p <- full_vip %>%
    filter(variable != "_full_model_") %>% 
    mutate(variable = fct_reorder(variable, dropout_loss)) %>%
    ggplot(aes(dropout_loss, variable)) 
  if(length(obj) > 1) {
    p <- p + 
      facet_wrap(vars(label)) +
      geom_vline(data = perm_vals, aes(xintercept = dropout_loss, color = label),
                 linewidth = 1.4, lty = 2, alpha = 0.7) +
      geom_boxplot(aes(color = label, fill = label), alpha = 0.2)
  } else {
    p <- p + 
      geom_vline(data = perm_vals, aes(xintercept = dropout_loss),
                 linewidth = 1.4, lty = 2, alpha = 0.7) +
      geom_boxplot(fill = "#91CBD765", alpha = 0.4)
    
  }
  p +
    theme(legend.position = "none") +
    theme_bw() +
    labs(x = metric_lab, 
         y = NULL,  fill = NULL,  color = NULL)
}
  
vip_bag <- model_parts(explainer_bag, loss_function = loss_root_mean_square)

ggplot_imp(vip_bag)

6.4.3 Floresta aleatória

O método random forest é definido via rand_forest. Este método não tem como arumento o custo de complexidade, \(\alpha\), sendo a complexidade da árvore controlada apenas via número mínimo de observações por partição, min_n. O hiperparâmetro m, mtry, define o número máximo de preditores considerados via sorteio em cada particionamento binário, para decorrelacionar as árvores. Por fim, é possível otimizar o número de bootstraps/árvores.

rf_model <- 
  rand_forest(mtry = tune(), 
              min_n = tune(), 
              trees = tune()) |>
  set_engine("ranger") |>
  set_mode("regression")

Definindo o grid para floresta aleatória. Deve-se utilizar o comando finalize para o mtry, de forma o grid seja definido considerando o número de prditores, \(K\), no conjunto de dados em análise. Posteriormente, realizam-se as partições nos dados para validação cruzada.

rf_grid <- grid_regular(
